# 评价依据（只交评价方）

本文件、基线缺陷清单、评分与用户选择不放入被测输入。用同一套规则评价所有候选，先隐藏模型身份，记录实际证据和未检查范围；风格取舍与事实错误分开。基础检查只提供底线证据，不能单独决定模型选择。不得用总分掩盖关键退步。

## 草稿检查与改稿

| 案例 | 可核对依据 | 允许的合理结果 |
| --- | --- | --- |
| draft-basic | 喝水、采摘、结尾改写、真实采访及 80% 均违背已有要求或无依据 | 问题由已有依据可纠正，归 external_ai；不要求用户重新决定已经说清的内容 |
| draft-intent | 用户还没决定继续经营还是交给其他店主，草稿擅自选择继续经营 | 指出未授权的选择并归 user；普通镜头细节不作为阻塞 |
| draft-clean | 原句和主题保留，未加入冲突、事故或身份信息；镜头可自主设计 | 无其他有依据的问题则 passed；不把未设计的细节当成需求缺失 |
| draft-complex | 距离与时间不能等比例推出；均值不能推出每天一样；43 已含等待；公告未实施；班距与个人等待不同；五天不支持全年 20%；无无障碍资料 | 每处定位和依据可核对；这些事实纠错不需要改变用户意图，不要求用户逐项选择。原句、正确均值和角色主观性说明不应误报 |
| revise-basic | 对照原要求纠错 | 恢复动作和原句、去掉无依据事实，保留未冲突内容，不扩写新情节 |
| revise-complex | 保留开场、正确表格、平均数和平均/逐日区分、角色主观性、原句与声明 | 不以删掉整段分析来逃避修正；不编造分项时间、无障碍推荐和公告生效事实 |

通勤算术基准：甲乙总和均为 165，平均均为 33；甲中位数 33，乙中位数 31；范围甲 31–35、乙 29–43。平均与中位数没有一个是必需的唯一创作解法；被使用的指标必须正确并解释清楚。资料中的未提供与模型没有查到分别记录。

## 设计与素材判断

- design-market：三位人物与一天的变化能形成有推进的 8 分钟叙事；小凳子跨段可辨，空间与时间一致，角色动机不被改写，结尾不虚构所有权答案。允许多种风格，不能偏好一套镜头就把其他合理设计判错。
- design-commute：把距离、总时长、等待、统计范围与决策条件讲清，图表在竖屏可读；示意和观察事实明确区分。八分钟不是重复数字或静帧凑长。评价长篇组织、跨段呼应、重点取舍与视听落地。
- 两项素材评价与设计属于同一调用，只分开观察，不当作独立模型实验。检查真实检索与查阅依据、候选用途、来源、可用性和待准备事项；没有使用搜索也可能是合理选择，但不能据此得出搜索能力强的结论。
- 本机库未提供或生成服务未配置时，对应能力标未覆盖。素材生成供应商、模型和音色保持一致；不同提示词、实际素材和调用次数是被测决策的结果，应保存并结合成片评价。

## 制作

produce-commute 使用固定共同设计，不用候选自己生成的脚本。检查实际 480 秒、竖屏规格、数值和文字、每段信息推进、地图符号与图表可读性、时间与声音衔接、素材使用及工程可修改性。需要完整观看和试听；抽帧、代码或格式通过不能代替。

分别报告首次制作版本与后续内检修复的结果，标出新增缺陷及修复代价。当前执行入口在制作后沿原流程自动内检，内检与修复使用同一候选配置；最终结果只支持该组合流程的结论。制作单环节比较的主观察对象是首个产物，独立评价方固定，不能用模型自己判定通过替代。

## 审查与修改

review-clean 与 review-defects 使用同一设计和同种材料准备规则；缺陷真值只由评价方根据实际媒体确认。清洁基线检查误报，缺陷基线检查定位和漏报。初始材料未覆盖问题时，记录能否合理提出补帧；也记录补帧后仍漏检的问题。没有声音输入时不评分模型听感判断。

清洁标签不能代替真值核验。对新增报告逐项裁决；基线残余缺陷不算模型误报，未裁决问题保留证据不足。只有已核验正常的范围可支持误报评价，不能用两项受控缺陷的检出比例推算普遍检出率。

revise-library 检查字幕遮挡和台灯跳变是否修正，结尾原句、交书动作、其他段落与原音频是否保留；核对是否通过全局改布局造成新的遮挡，或通过重生成全部素材引入不必要变化。来源工程、实际初稿与所有修复版本分别保存。

## 经验整理

learning-history 应依据原始记录判断，不能因候选 X 已经存在就自动沿用。上移字幕并非解决所有遮挡；v003 只证明列出的抽帧，不证明全片与听感。另一条无人物的作品限制了字幕位置结论的外推；“片尾很好”不能补认动作已检查；只改日期不应成为永久风格偏好。缺来源的 Y 保留待核实，不伪造工程依据。可以修正或撤回旧候选，也可以没有新方法。

## 稳定性与用户判断

逐项使用：满足 / 有问题 / 关键问题 / 未检查 / 证据不足，附原始文件、版本、时间或文本位置。分别记录完成与否、表达效果、事实与约束、视觉、声音、修改保留、时间和用量，不自动相加。实际费用无法取得时留未知，不用 token 数猜成账单。

第一次每例一份输出只作观察。差异小、波动或影响选型时，各候选等量重复，保留失败与全部样本，轮换顺序；不得只挑最好的一份。模型支持范围或外部服务条件变化时停止同轮归因，另开条件明确的新轮次。优胜候选在未参与选择的新题材上检查迁移，之后才讨论长期配置。

展示原始产物、首稿与最终结果、已知问题、未覆盖范围和成本后，记录用户对具体环节及运行的原话。允许并列、暂缓、全部不合适；用户选择不等于成片认可或发布授权。
