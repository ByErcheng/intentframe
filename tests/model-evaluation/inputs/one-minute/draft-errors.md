# 一分钟草稿检查：共享雨伞

原始要求：60秒竖屏，用虚构社区雨伞站解释登记次数与流转。周一至周四借出依次12、18、15、15次，归还依次9、16、17、18次，开始累计未还0。没有唯一编号、实物盘点、天气强度与满意度资料。归还可能对应此前借用。公告为“拟增设晚间归还点，具体日期另行公告”。保留结尾“看清流转，再谈损耗。”和合成声明；只依据这些资料纠错，不为已有事实再要求用户决定。

待检查草稿：雨天访客拿起蓝伞，登记后走出入口。用四天表展示借出12、18、15、15，归还9、16、17、18。两组总数都是60，所以四天每天借还相同，每个人都在当天还了伞。周二18个人借伞，16人归还，证明丢了2把；周三借出15次而归还17次，是不可能的数据，应删掉这天。图中的“累计未还”画为3、2、-2、-3，宣称负数意味着多买了伞。把归还线除以当天借出得到比例，超过100%时截断到100%，标为“实名用户归还率”。雨越大，借出必然越多。下周晚间归还点已正式开放，保证全年损耗降低50%。最后访客将蓝伞交给值守者，双手接稳再放回伞架。片尾“看清流转，再谈损耗。”及“虚构场景与合成登记数据”。

本轮只检查草稿，返回可定位的问题、依据与处理归属。原表、开场及结尾本来正确，不应一并删除或改写。
