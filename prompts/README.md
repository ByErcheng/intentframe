# 提示词维护

本目录是可维护提示词正文与模板的入口。代码通过 [prompts.ts](../src/runtime/prompts.ts)读取，执行流程与校验仍由源码承担；需求、反馈和每次实际输入留在本机作品目录。

| 文件 | 内容与使用方式 |
| --- | --- |
| [production.md](./production.md) | 制作与修改的“执行约束”和“启动消息”；分别用于会话开发指令与本轮启动输入，不整文件发送。 |
| [asset-acquisition.md](./asset-acquisition.md) | 设计与制作共用的素材获取原则，含来源判断、人声管理和不自动试听；两阶段都保存实际所用正文与摘要。 |
| [task.md](./task.md) | 本轮任务在前、必要依据在后、历史按需查阅的上下文模板，组装后写入本轮工程供主 AI 读取。 |
| [production-rules.md](./production-rules.md) | 样例制作、完整制作、反馈处理、局部定位、经验使用，分章节维护并按任务条件选取。 |
| [learning.md](./learning.md) | 独立经验整理的“执行约束”和“启动消息”；分别传入会话与轮次，整理材料保存在本轮上下文。 |
| [external-ai.md](./external-ai.md) | MCP 连接指引，详细调用方法仍以[使用说明](../scripts/README.md)为准。 |
| [authoring.md](./authoring.md) | 草稿入项检查、辅助改稿与视频设计，按阶段选取；检查只返回意见，正文和记录由系统保存。 |
| [review-materials.md](./review-materials.md) | 项目 AI 根据实际帧图核对设计实现、缺陷及材料覆盖，反馈内部修复与补帧要求；外部 AI 仍独立审查。 |
| [model-analysis.md](./model-analysis.md) | 制作素材方案与视觉材料理解，两章分别进入对应只读调用；模型与强度来自配置，不进入提示词。 |

## 组装与修改

制作每次只选“样例制作”或“完整制作”其中一章；存在相关反馈时选“反馈处理”，存在定位信息时再选“局部定位”，“经验使用”放在任务模板的经验部分。选择逻辑见 [productionRules](../src/runtime/context.ts)，消息发送与输入存档见[制作服务](../src/runtime/work-service.ts)。独立经验整理不附带制作条件规则，外部 AI 只从连接指引取得使用入口。

条件规则负责说明反馈如何适用，任务模板负责当前信息的排列与材料读取入口，避免在两处重复维护同一段规则。固定约束保留跨任务都适用的权限和交付要求。章节标题是读取标识，同一文件中须唯一；修改标题时同步调用方。缺失、重复或空正文会明确报错，不能回退到整文件发送。

制作条件规则以二级章节维护。[productionRuleContext](../src/runtime/context.ts)将本轮选中的阶段、素材、反馈及定位规则组装为“本轮任务”下独立的三级章节，内部标题相应下移，代码围栏内容不改动；缺少根标题、内部标题越出规则边界或超过六级时明确拒绝。经验规则仍放在模板的经验部分。来源存档保留原正文与摘要，组装后的实际上下文另行保存；检查层级时须以最终上下文为准。

### 正文组织

较长的提示词按目标、输入依据、执行边界、判断规则与输出要求分段，把同一判断所需的条件放在一起；短规则用自然段即可，不机械补齐标题。分段表达职责和适用条件，不规定模型的内部思考顺序，也不改变消息权限。只有交接存在实际先后关系时才使用步骤列表。

按章节读取的文件保留现有读取标题，内部说明使用更低层级的标题；[章节提取](../src/common/markdown.ts)会保留下级内容。相邻独立规则使用段落或列表区分，合并同一执行范围内的重复要求，不删减授权、失败处理和证据边界。不同阶段各自需要的约束保留在各自输入中。

格式容易误解时提供短例子，明确示例不构成本轮内容；字段与状态的精确含义沿实际输出契约，避免示例与规则矛盾。

技术规则写清可核对的条件与当前可用接口，保留构图、风格和实现方法的创作空间。帧渲染与可修改性放在制作约束，图片描述放在共用素材规则，实际画面和覆盖判断放在内检；不把某类作品的方法或其他工具的命令、权限和清理策略直接变成通用要求。提示词要求检查，不表示系统已经实现乱序渲染对比、逐帧闪烁检测或听音能力。

### 模板与输入存档

模板仅使用明确的文字占位符，不承载程序逻辑。新增或删除占位时同步组装入口与相关回归；必要输入缺少对应位置会明确失败，用户原文中的同形字符不会再次作为模板解析。

提示词纳入系统指纹，已受理请求不会悄悄按修改后的系统启动。制作在调用模型前保存实际开发指令、任务上下文、启动消息、输出格式及来源正文与摘要；整理任务在其上下文保存对应依据。章节来源记录文件路径、章节名称、实际选取正文及其 `sha256`，另用 `sourceSha256` 标识完整源文件版本；未选章节不会因合并文件而进入本轮提示词。历史输入仍以当时存档为准，不因原文件合并或删除而重写，记录位置见[制作输入与历史依据](../docs/data.md#制作输入与历史依据)。

长期业务规则仍以[协作约定](../AGENTS.md)、[制作流程](../docs/workflow.md)和[数据约定](../docs/data.md)为主定义。这里维护执行所需的简短指令，不复制完整文档章节；改动时核对是否仍保留授权、方向确认、资产保护和真实完成边界。

## 修改后的验证

按[系统回归入口与前提](../docs/maintenance.md#系统回归的范围)运行 `npm run check` 与 `npm test`。其中[提示词回归](../tests/prompts.test.ts)检查章节边界、条件选取、消息位置与历史输入保留；[请求规则回归](../tests/request-guidance.test.ts)检查占位替换及缺少输入时的拒绝，稿件、制作和内检回归覆盖各自交接流程。

标题组装及相关交接的定向复查可用以下入口，工具和依赖前提同上。测试文件串行执行，保留用例内既有超时与断言；串行通过不证明并行执行时的媒体超时已解决。

```sh
node --test --test-concurrency=1 tests/prompts.test.ts tests/authoring.test.ts tests/external-interface.test.ts tests/production-handoff.test.ts
```

这些检查不证明模型理解或作品效果已改善。需要判断效果时，以相同输入和可比执行条件比较实际结果，检查原意保留、要求覆盖、阻塞判断、授权边界和输出可用性；未做模型对比时只报告结构与系统行为的验证结果。
