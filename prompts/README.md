# 提示词维护

本目录是可维护提示词正文与模板的入口。代码通过 [prompts.ts](../src/runtime/prompts.ts)读取，执行流程与校验仍由源码承担；需求、反馈和每次实际输入留在本机作品目录。

| 文件 | 内容与使用方式 |
| --- | --- |
| [production.md](./production.md) | 制作与修改的“执行约束”和“启动消息”；分别用于会话开发指令与本轮启动输入，不整文件发送。 |
| [task.md](./task.md) | 本轮任务在前、必要依据在后、历史按需查阅的上下文模板，组装后写入本轮工程供主 AI 读取。 |
| [production-rules.md](./production-rules.md) | 样例制作、完整制作、反馈处理、局部定位、经验使用，分章节维护并按任务条件选取。 |
| [learning.md](./learning.md) | 独立经验整理的“执行约束”和“启动消息”；分别传入会话与轮次，整理材料保存在本轮上下文。 |
| [external-ai.md](./external-ai.md) | MCP 连接指引，详细调用方法仍以[使用说明](../scripts/README.md)为准。 |
| [authoring.md](./authoring.md) | 草稿修改与视频脚本设计，按阶段选取；只读生成正文，文件由系统保存。 |
| [review-materials.md](./review-materials.md) | 项目 AI 根据实际帧图核对设计实现、缺陷及材料覆盖，反馈内部修复与补帧要求；外部 AI 仍独立审查。 |

## 组装与修改

制作每次只选“样例制作”或“完整制作”其中一章；存在相关反馈时选“反馈处理”，存在定位信息时再选“局部定位”，“经验使用”放在任务模板的经验部分。选择逻辑见 [productionRules](../src/runtime/context.ts)，消息发送与输入存档见[制作服务](../src/runtime/work-service.ts)。独立经验整理不附带制作条件规则，外部 AI 只从连接指引取得使用入口。

条件规则负责说明反馈如何适用，任务模板负责当前信息的排列与材料读取入口，避免在两处重复维护同一段规则。固定约束保留跨任务都适用的权限和交付要求。章节标题是读取标识，同一文件中须唯一；修改标题时同步调用方。缺失、重复或空正文会明确报错，不能回退到整文件发送。

模板仅使用明确的文字占位符，不承载程序逻辑。新增或删除占位时同步组装入口与相关回归；必要输入缺少对应位置会明确失败，用户原文中的同形字符不会再次作为模板解析。

提示词纳入系统指纹，已受理请求不会悄悄按修改后的系统启动。制作在调用模型前保存实际开发指令、任务上下文、启动消息、输出格式及来源正文与摘要；整理任务在其上下文保存对应依据。章节来源记录文件路径、章节名称、实际选取正文及其 `sha256`，另用 `sourceSha256` 标识完整源文件版本；未选章节不会因合并文件而进入本轮提示词。历史输入仍以当时存档为准，不因原文件合并或删除而重写，记录位置见[制作输入与历史依据](../docs/data.md#制作输入与历史依据)。

长期业务规则仍以[协作约定](../AGENTS.md)、[制作流程](../docs/workflow.md)和[数据约定](../docs/data.md)为主定义。这里维护执行所需的简短指令，不复制完整文档章节；改动时核对是否仍保留授权、方向确认、资产保护和真实完成边界。
